# StyleMate AI

Рабочий прототип онлайн-стилиста без загрузки фотографий и без API-ключей. Пользователь выбирает бюджет и один из трех сценариев, а сервис возвращает 3 разные подборки вещей с прямыми ссылками на товары.

## Что есть

- мобильный премиальный интерфейс в черно-белой гамме;
- анкета без фото, телефона, мерок и OpenAI API key;
- выбор аудитории: только `Девушка / женщина`;
- 3 сценария: офис и встречи, повседневная одежда, вечерние наряды;
- подборка из 3 разных луков;
- каждый лук состоит из верха, низа, сумки, обуви и аксессуаров;
- карточки товаров с брендом, ценой, цветом, артикулом и ссылкой;
- общий список покупок и копирование текстового списка;
- состояния пустого результата, загрузки и ошибки;
- простой Node.js server для локального запуска и Timeweb health check.

## Запуск

```bash
cd ai-online-stylist
npm start
```

Откройте:

```text
http://127.0.0.1:8012/ai-online-stylist/
```

## Настройки (`.env`)

Секреты и переключатели лежат в файле `.env` (шаблон — `.env.example`). Файл `.env` нельзя загружать в GitHub.
На Timeweb те же переменные задаются в панели: «Настройки деплоя» → «Переменные».

| Переменная | Что делает |
| --- | --- |
| `OPENAI_API_KEY` | Ключ OpenAI. Без него сервис подбирает образ по правилам, а фото человека не анализируется |
| `OPENAI_MODEL` | Модель ChatGPT с поддержкой картинок (по умолчанию `gpt-4o`) |
| `OPENAI_BASE_URL` | Адрес API; менять только если используете шлюз вместо api.openai.com |
| `OPENAI_PROXY_URL` | Зарубежный прокси `socks5://логин:пароль@адрес:порт` (или `http://...`) только для запросов к ChatGPT. Спецсимволы в логине и пароле кодируются (`@` → `%40`, `:` → `%3A`). Нужен пакет `undici` (`npm install`). Telegram и магазины ходят напрямую |
| `TELEGRAM_BOT_TOKEN` | Токен бота от @BotFather; нужен, только если сервер сам обращается к Telegram (сейчас не используется) |
| `PARSE_PROXY_URL` | Отдельный прокси для сайтов магазинов; нужен, только если сервер находится вне России |
| `LOOKS_COUNT` | Сколько образов собирать в одной подборке: 2 (по умолчанию) или 3 |
| `LOOKS_SOURCE` | `local` — вещи из `data/curated-catalog.json`; `parse` — парсить сайты магазинов из `data/brand-sources.json` (фоном, раз в `PARSE_REFRESH_HOURS` часов). Если спарсилось мало, автоматически берётся `local` |
| `AI_RENDER_ENABLED` | `false` отключает картинку образа на манекене (платная функция). По умолчанию включена, если задан ключ OpenAI |
| `OPENAI_IMAGE_MODEL`, `OPENAI_IMAGE_QUALITY` | Модель и качество картинки (по умолчанию `gpt-image-1.5`, `medium`; `low` дешевле, `high` дороже) |
| `AI_RENDER_PER_HOUR`, `AI_RENDER_DAILY_LIMIT` | Лимиты генераций картинок с одного адреса в час (6) и всего за сутки (200). Одна подборка из 2 образов тратит 2 картинки |
| `CATALOG_CHECK_HOURS` | Как часто проверять ссылки каталога (по умолчанию каждые 6 часов, `0` выключает). См. раздел «Свежесть каталога» |
| `LOGS_TOKEN` | Секретная строка для просмотра логов в браузере: `https://ваш-домен/api/logs?token=...` (последние 500 строк). Без неё страница логов выключена |
| `AI_RATE_PER_HOUR`, `AI_DAILY_LIMIT` | Ограничения запросов к ChatGPT с одного адреса в час и всего за сутки |

Как это работает с ChatGPT: пользователь загружает фото вещи и (по желанию) своё фото. ChatGPT описывает вещь, определяет цветотип по фото
(тон кожи, волосы, глаза, подходящие и неподходящие цвета) и выбирает вещи из каталога выбранного источника. Выбор проверяется сервером:
товары должны быть из каталога, а сумма — укладываться в бюджет. Если ChatGPT недоступен, образ подбирается по правилам.

Важно: OpenAI не принимает запросы с серверов в России, поэтому при хостинге в России нужен `OPENAI_PROXY_URL` с зарубежным IP. Проверить связь можно командой `node tools/check-connections.mjs` (в консоли приложения на Timeweb): она покажет, работают ли Telegram и ChatGPT.

## Образы и картинки на манекене

Сервис собирает несколько разных образов (по умолчанию два, `LOOKS_COUNT`) вокруг вашей вещи. С ChatGPT оба образа подбираются одним запросом, а сервер проверяет, что товары из каталога, каждый образ укладывается в бюджет и товары в образах не повторяются. Без ChatGPT образы подбираются по правилам.

Для каждого образа ChatGPT (OpenAI Images) получает фото вашей вещи и фото выбранных товаров из каталога и рисует всё на безликом белом манекене. Картинки рисуются параллельно в фоне (1–2 минуты), подборка доступна сразу; на вкладках «Образ 1 / Образ 2» видно, готова ли картинка, по нажатию она открывается на весь экран, при ошибке есть кнопка «Повторить». Адреса товаров сервер берёт только из своего каталога, чужие адреса игнорируются.

## Логи

Сервер пишет всё в стандартный вывод одной строкой с временем и меткой раздела. Секреты, ключи и фото в логи не попадают, прокси показывается без логина и пароля.

| Метка | Что записывается |
| --- | --- |
| `[server]`, `[config]` | запуск, версия Node, какие настройки заданы (только «задан/не задан»), остановка и падения процесса |
| `[http]` | запросы (без служебных `/api/status` и обычных файлов сайта): метод, адрес, код ответа, время; для главной ещё тип устройства (ios, android, telegram, компьютер). Ошибки 4xx и 5xx всегда |
| `[catalog]` | какой каталог отдан (`local` или `parse`), результат парсинга магазинов, причины отката |
| `[health]` | проверка ссылок каталога: сколько рабочих, какие исключены и почему, изменения цен и наличия, тревоги по категориям |
| `[ai]` | каждый запрос к ChatGPT: сколько кандидатов, модель, прямой запрос или через прокси, время ответа, отклонённые попытки, ошибки OpenAI |
| `[render]` | генерация картинки образа: принято ли задание, сколько картинок товаров удалось получить, время ответа OpenAI, причины отказов |
| `[telegram]` | вызовы Bot API и их результат |
| `[client]` | события из браузеров: итог подбора (`submit_ok` или `submit_error` с названием шага, где остановилось) и необработанные ошибки страницы (`js_error`) |

Где смотреть:
1. В панели Timeweb: «Логи приложения».
2. В браузере: `https://ваш-домен/api/logs?token=ВАШ_LOGS_TOKEN` (нужна переменная `LOGS_TOKEN`). Работает, даже если панель логов пустая.
3. В консоли приложения: `pm2 logs --nostream --lines 100`.

Если в панели Timeweb логи пустые, а на странице `/api/logs` строки есть, значит, панель не получает вывод приложения под `pm2`. Тогда в «Настройках деплоя» замените команду запуска на `pm2-runtime start server.mjs`.

## Свежесть каталога

Ссылки на товары устаревают: карточку снимают, товар заканчивается, цена меняется. Поэтому сервер сам проверяет каталог (и `local`, и `parse`): через минуту после запуска и затем раз в `CATALOG_CHECK_HOURS` часов открывает карточку каждого товара.

- **Ссылка умерла:** ответ 404 или 410, редирект на главную, страница «не найдена». Такая проверка повторяется сразу ещё раз, и только подтверждённая мёртвая ссылка исключается из выдачи (из образов и из подбора ChatGPT). Если ссылка снова заработает, товар возвращается.
- **Проверить не удалось** (магазин не ответил, отдал защиту от ботов, 401, 403, 5xx, `robots.txt` запрещает): товар остаётся как есть, он не считается мёртвым.
- **Цена и наличие:** обновляются из самой карточки, если она отдаёт структурированные данные. Товары «нет в наличии» в образы не попадают.
- **Предохранители:** если за один проход «умирает» больше половины каталога, это считается блокировкой проверки, и ничего не исключается. Категория не остаётся совсем пустой: оставляются самые «живые» из мёртвых и в журнал пишется тревога `[health] в категории … осталось рабочих товаров`.
- **Парсинг (`LOOKS_SOURCE=parse`)** пополняет каталог новыми товарами, а категории, где спарсилось мало, добираются из локального каталога.

Результаты хранятся в `data/catalog-health.json` (создаётся сам). Проверить каталог вручную и посмотреть список по каждой ссылке: `node tools/check-catalog.mjs`. Мёртвые товары стоит убрать из `data/curated-catalog.json` совсем, а в журнале (`[health]`) видно, какие именно.

## Мужские образы

В форме можно выбрать «Парень / мужчина»: подписи (категории вещи, повод «вечерний выход»), палитры и подбор переключаются. Мужской каталог лежит в `data/curated-catalog-men.json` (сейчас Befree и Sela, по 5–12 товаров в каждой из пяти категорий), у каждого товара поле `gender`. Женский каталог остаётся прежним, и мужские и женские товары не смешиваются: ни в подборе по правилам, ни в запросе к ChatGPT, ни на картинке (манекен рисуется мужской или женский).

- **ChatGPT:** получает пол клиента и только товары нужного пола (или `unisex`).
- **Без ChatGPT:** для мужчин работает отдельный простой движок: по поводу берутся предпочтительные и нежелательные типы вещей (например, для офиса рубашка и брюки, без худи и кроссовок), бюджет, и товары в образах не повторяются. Женский движок не менялся.
- **Парсинг (`LOOKS_SOURCE=parse`):** мужские разделы Befree и Sela описаны в `data/brand-sources.json` с полем `"gender": "men"`. Для мужских источников отсеиваются явно женские вещи (каблуки, юбки, подвески и т. п.), потому что в мужском разделе Befree такие встречаются.
- **Обновить мужской каталог:** `node tools/seed-curated.mjs men` (занимает 1–3 минуты, перезаписывает `data/curated-catalog-men.json`).
- Проверка живости ссылок (`[health]`) работает и для мужского каталога.
- Каталог пока узкий: два магазина. Ralf Ringer (мужская обувь и сумки) не подключён: его товары подгружаются скриптами, обычный парсинг их не видит.

## Каталог

Основной каталог лежит в:

```text
data/curated-catalog.json
```

Если нужно добавить новые магазины или заменить товар, добавьте карточку товара в этот файл. Чем точнее `url`, `name`, `color`, `visual` и `image`, тем честнее будет подборка.
